## Problem

Relay currently lacks reproducible benchmarks measuring MongoDB query contention when event ingestion and delivery workers operate concurrently.

We need evidence to understand throughput, latency, connection-pool pressure, and contention before making database-level optimization decisions.

## Deliverables

### 1. Benchmark harness

Create `bench/mongo-contention/` containing:
- [ ] A reproducible concurrent event-ingestion and delivery workload.
- [ ] Configurable concurrency, request rate, and workload duration.
- [ ] Configurable MongoDB connection-pool settings.
- [ ] Separate measurements for ingestion and delivery operations.
- [ ] Documented environment and execution instructions.

### 2. Metrics

Capture:
- [ ] Operations per second.
- [ ] p50, p95, and p99 latency.
- [ ] Error and timeout rates.
- [ ] MongoDB connection-pool utilization and wait time, where observable.
- [ ] CPU and memory usage where practical.
- [ ] Results under ingestion-only, delivery-only, and mixed workloads.

### 3. Results

Publish results in `docs/benchmarks/mongo-contention.md`.

Include hardware, MongoDB version, configuration, workload parameters, raw results or reproducible output, and limitations.

### 4. Recommendations

Provide evidence-backed recommendations for:
- [ ] Below 100 events/second.
- [ ] 100–1,000 events/second.
- [ ] Above 1,000 events/second.

Evaluate connection-pool sizing, query patterns, indexes, batching, and worker concurrency. Do not recommend settings without supporting measurements.

## Acceptance Criteria

- [ ] Benchmark harness runs against a documented MongoDB environment.
- [ ] Concurrent ingestion and delivery are measured.
- [ ] Baseline and mixed-workload results are recorded.
- [ ] p50, p95, and p99 latency are reported.
- [ ] Throughput and error rates are reported.
- [ ] Results are reproducible using documented commands.
- [ ] Recommendations address all three throughput ranges.
- [ ] Findings distinguish measured results from assumptions.
- [ ] No production application code or runtime behavior is changed.

## Expected Files

- `bench/mongo-contention/`
- `docs/benchmarks/mongo-contention.md`

## Constraints

This is a benchmark and investigation task only. Do not modify production handlers, database models, indexes, or worker behavior. Use an isolated test database and avoid production workloads.
